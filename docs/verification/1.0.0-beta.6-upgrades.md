# Beta 6 migration verification

The first [release run](https://github.com/peterthepeter/groly/actions/runs/39476713164)
failed before image promotion. Its comparison required every table schema and
checksum to remain identical, including `__drizzle_migrations`. Migration 0050
legitimately appends a ledger record and adds nullable `user_invites.token_value`.
No Docker version/channel tags were promoted by that failed run.

The corrected verifier derives the expected schema from the actual pending SQL.
It permits only additive nullable columns without defaults; any other migration
requires an explicit data-conversion contract. Existing columns, row counts and
all existing row values (including associations) must remain unchanged. New
columns must be null. Existing migration records must be unchanged and the new
records must match the exact pending SQL hashes and journal timestamps. Restarts,
failed startup and restore still use the original strict comparison.

The fixture now includes existing hashed invitation links, and Beta 5 is included
in the default upgrade matrix alongside the supported stable baselines.

# Beta.3 release verification failure

[Run 38780170806](https://github.com/peterthepeter/groly/actions/runs/38780170806)
failed in WebKit's offline home-navigation assertion. The image was not promoted.

The trace records the initial `/api/lists` request at 38360 ms, followed by
navigation to the recipe at 38385 ms. WebKit reports `Load request cancelled`.
The home list catalog was therefore never cached. Later, while offline, the
test incorrectly expected that list catalog to be available. The authenticated
home HTML itself loaded with status 200 and rendered a styled empty-list view.

The test now waits for the initial list to be visible and present in IndexedDB
before navigating away. Its initial list request is deliberately held until
service-worker readiness to exercise slow loading without arbitrary sleeps.
No assertions, timeouts or application code were weakened or changed.

Local verification used the exact unchanged registry candidate:
`ghcr.io/peterthepeter/groly@sha256:a7ea12c9c3d269bedc9752905035fe37e36922f06b0144d614d012b17c4143d9`.
The corrected offline scenario passed three consecutive WebKit runs and one
Chromium run. Registry-image upgrade/restore checks passed for all three stable
baselines; image scanning found zero vulnerabilities. The complete CI run is
failed. Its failed result is retained as evidence.

At diagnosis, confirmed channel digests were unchanged:

- `:beta` (beta.2): `sha256:024bca85f221788342b6376cd0da6814d15b789b3e0fe218b3147df8f4881bf1`
- `:latest` (0.9.10): `sha256:29f206017045e27a1b7f41d21b697ed25f6c6c7e7af87228eeca4a0a046756ff`

The published beta.3 release notes identified the blocked Docker publication.
The user subsequently authorized replacing the beta.3 tag with the test-only
correction and starting exactly one further release verification. The application
code, dependencies, version and changelog are unchanged by this correction.

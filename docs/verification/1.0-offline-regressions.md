# Local offline regression verification

This report records local development and verification on `codex/groly-1.0`
before release authorization. These checks used package version `1.0.0-beta.2`
and did not change published images. The corrections are included in the
subsequently authorized [1.0.0-beta.3 release](../releases/1.0.0-beta.3.md).

## Corrections

- Item edits and deletions join the same durable FIFO queue as item creation.
  A confirmed write supplies the revision for subsequent edits to that item.
  Already-applied retries are acknowledged; conflicting remote values still
  follow the existing conflict policy.
- Pending and recently confirmed changes survive overlapping GET/SSE refreshes.
  An older response cannot restore an unchecked or deleted item after sync.
- Shopping favorites are cached per account. Offline additions/removals are
  durable and ordered, including retries after a proxy rejection. Refreshing
  account settings preserves the favorites cache.
- Recipe navigation uses the existing root authentication and user data rather
  than redundant page server loaders. Cached ingredients and instructions are
  usable offline; missing details show a localized recovery view.
- A full navigation without cached HTML displays a self-contained, precached
  German/English offline page. Old HTML is not served under an unrelated URL.
  HTML caches are separated by build; existing data caches and IndexedDB remain.
- Redirected login responses are excluded from the HTML cache. After login, the
  worker refreshes the authenticated home document so the fallback's home button
  works offline even when the first service-worker installation was on `/login`.
- Root-relative application assets avoid incorrect paths on nested routes.
  PDFMake font URLs are resolved absolutely so PDF export remains functional.

There is no SQLite migration or IndexedDB schema-version change. New local
cache metadata is optional. Both languages are documented in the InfoModal.

## Automated coverage

- Unit/integration tests: local create/check/edit ordering, lost responses,
  genuine conflicts, overlapping refreshes, cache persistence, account isolation,
  favorites ordering and proxy retries.
- Chromium and WebKit: offline create/check, reload before sync, cached favorites,
  offline favorite addition/removal, exactly one server item, checked state on a
  second online client through SSE, cached recipe ingredients/instructions,
  uncached recipe feedback, cold navigation fallback, return home and retry,
  small-screen light/dark fallback, and no uncaught page errors.
- Existing browser upgrade: installed 0.9.10 PWA, existing session and pending
  mutation retained, tracker/recipe/settings navigation, offline PDF assets,
  repeated PDF downloads after reconnect, meal-plan date and language persistence.
